# Unity and plastic connection

*Read when: a page has strong individual sections and feels like several
different designs, or when reviewing a long page as a whole. Supports
[C2](../SKILL.md#invariant) and [C11](../SKILL.md#invariant).*

---

## The test

**Does this operate as one work, or as a sequence of independently designed
sections?**

The failure is easy to miss because it is invisible section by section. Every
passage reviews well; the page does not. Reviewing at section scale — which is how
components are built and how design tools are used — systematically hides it.

Judge unity by scrolling the whole page at 25–40% zoom, or as a strip of
thumbnails. Autonomous sections are obvious there and nowhere else.

## What actually creates unity

Not "using the same components". Components give consistency, which is a
production property. Unity is compositional:

- **Recurring shapes** — a proportion, a silhouette, a mass ratio that reappears.
- **Related proportions** — masses drawn from a small set of ratios rather than
  arbitrary sizes ([C8](../SKILL.md#invariant)).
- **Repeated directions** — the same diagonal, the same axis, the same lean,
  showing up in image, type and layout.
- **Scale families** — a limited set of sizes, so a new size *means* something.
- **Alignment relationships** — shared axes that survive across sections, even
  when the sections differ in every other way.
- **Continuation of movement** — a force started in one passage picked up by the
  next ([C11](../SKILL.md#invariant)'s hand-off).
- **Tonal continuity** — the value structure holds across the page; the field does
  not restart at every section.
- **Correspondence of filled and empty** — the ratio between mass and space stays
  in a family, so the page breathes at one rate.
- **Common edge behaviour** — if images bleed, they bleed; if content insets, it
  insets. Mixed edge logic reads as two designs.
- **Recurring intervals** — the meter under the rhythm
  ([rhythm-interval-and-pause](rhythm-interval-and-pause.md)).

**Unity does not mean uniformity.** Three differently-cropped, differently-sized
images unified by one reasoning are more unified than three identical ones placed
by habit. The question is whether the differences follow a single logic.

## Plastic connection

The academic term for the physical hand-off between passages: what one mass gives
the next, and how the next receives it.

Ask at every boundary:

1. What force arrives here — a direction, a tonal weight, an unresolved tension?
2. What receives it — an aligned edge, an answering mass, a tonal change, a pause?
3. If nothing receives it, the force dies at the boundary and the next section
   starts from zero. That is autonomy, and it is what makes a long page feel like
   scrolling rather than reading.

Bridges are usually small: a shared axis, a continuing tonal field, an image whose
subject faces the following section, an interval that belongs to both sides.

## Symptoms of weak unity

| Symptom | What it actually is |
|---|---|
| "Each section is nice, the page isn't" | Autonomous sections; no plastic connection |
| "It looks like three different sites" | Competing compositional systems — one section symmetric, another asymmetric, a third modular |
| "It's consistent but boring" | Uniformity mistaken for unity; meter with no rhythm |
| "Something changes halfway down" | Accidental style shift — usually a section built later, or by someone else |
| "Too much variety" | Every section departs, so no departure registers |
| "Repetitive but disconnected" | Same components everywhere, no shared axes, proportions or forces |

## Multi-page and multi-state unity

A site is one work too. The same test applies across pages, and across the states
of one page — open menu, error, empty, loading, long content, logged in.

**States are compositions nobody composes.** The empty state, the error state and
the ten-items-instead-of-three state are where unity breaks first, because they
were never drawn. Name the states that change the mass structure and compose them
as compositions, not as edge cases.

## Repairing unity without redesigning

In order of cost:

1. **Unify the intervals** — bring between-passage gaps into one family. Cheapest,
   and it fixes "disconnected" more often than anything else.
2. **Unify edge behaviour** — decide bleed or inset per element type, and apply it.
3. **Unify the scale family** — collapse the sizes in use to a smaller set.
4. **Restore a shared axis** — one alignment line running the length of the page.
5. **Add bridges** — a continuing tonal field, or an image direction that leads
   into the next passage.
6. **Only then** reconsider the mass schemes of individual passages.
